## 📋 OVERVIEW

Nexzy requires 3 environment files for full operation:

1. **nexzy-backend/.env**   - Backend API configuration (Supabase, API, Scraper)
2. **nexzy-frontend/.env**  - Frontend configuration (Supabase anon key, API URL)
3. **ai-service/.env**      - AI service configuration (Gemini API)

## 🚀 QUICK SETUP (5 MINUTES)

### Step 1: Backend Environment
```bash
cd nexzy-backend
cp .env.example .env
```

Edit nexzy-backend/.env with your credentials:
- SUPABASE_URL              → From Supabase dashboard
- SUPABASE_SERVICE_ROLE_KEY → ⚠️ SECRET! Backend only!
- SUPABASE_JWT_SECRET       → For token verification
- TARGET_DOMAIN             → Domain to monitor (e.g., ui.ac.id)
- AI_SERVICE_URL            → http://localhost:8000 (AI service endpoint)
- API_PORT                  → 8001 (Backend API port)

### Step 2: Frontend Environment
```bash
cd nexzy-frontend
cp .env.example .env
```

Edit nexzy-frontend/.env:
- VITE_SUPABASE_URL      → Same as backend
- VITE_SUPABASE_ANON_KEY → ✅ PUBLIC key (not service role!)
- VITE_API_URL           → http://localhost:8001 (Backend URL)

### Step 3: AI Service Environment
```bash
cd ai-service
cp .env.example .env
```

Edit ai-service/.env:
- GEMINI_API_KEY → From https://aistudio.google.com/app/apikey

## 🔑 GETTING CREDENTIALS

### Supabase Credentials
1. Buka https://app.supabase.com
2. Pilih project Nexzy
3. Go to: Settings > API
4. Copy values:
   - Project URL → SUPABASE_URL
   - anon public key → VITE_SUPABASE_ANON_KEY (frontend)
   - service_role key → SUPABASE_SERVICE_ROLE_KEY (backend only!)
5. Go to: Settings > API > JWT Settings
   - JWT Secret → SUPABASE_JWT_SECRET

### Gemini API Key (FREE!)
1. Buka https://aistudio.google.com/app/apikey
2. Sign in dengan Google account
3. Click "Create API Key"
4. Copy key (starts with "AIza...")
5. Paste ke ai-service/.env

# ==============================================================================

## 🔒 SECURITY CHECKLIST

✅ DO:
- Use service_role key ONLY in backend
- Use anon key in frontend
- Keep .env files local (never commit to Git)
- Use different values for dev/staging/prod
- Enable Supabase RLS (Row Level Security)

❌ DON'T:
- Never commit .env files to Git
- Never use service_role key in frontend
- Never share API keys publicly
- Never hardcode secrets in code

## 🐛 TROUBLESHOOTING

### Backend won't start
- Check SUPABASE_SERVICE_ROLE_KEY is correct (not anon key!)
- Verify SUPABASE_URL format: https://xxxxx.supabase.co
- Check port 8001 is not in use (backend uses 8001, not 8000!)
- Run: .\start.ps1 or uvicorn api.main:app --port 8001

### Frontend can't connect
- Check VITE_API_URL points to backend (http://localhost:8001)
- Verify CORS_ORIGINS in backend includes frontend URL
- Check VITE_SUPABASE_ANON_KEY (not service_role!)
- Backend must be running on port 8001

### AI service errors
- Check GEMINI_API_KEY is valid
- Verify API key starts with "AIza"
- Check internet connection (API calls need internet)
- Verify you haven't hit rate limit (15 req/min for free tier)

## 🚀 STARTUP SCRIPTS

Use these convenience scripts to start all services:

### Start All Services (Root)
```bash
cd C:\Users\[username]\Documents\My Projects\nexzy
.\start-all.ps1
```

This will:
1. Start AI Service on port 8000
2. Start Backend API on port 8001  
3. Start Frontend on port 5173

### Individual Services
```bash
# AI Service (Terminal 1)
cd ai-service
.\start.ps1

# Backend (Terminal 2)
cd nexzy-backend
.\start.ps1

# Frontend (Terminal 3)
cd nexzy-frontend
npm run dev
```
